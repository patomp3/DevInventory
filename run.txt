วิธีรัน Dev Inventory บนเครื่อง (Windows + Docker Desktop)
==========================================================
อัปเดต: 2026-11-05

สิ่งที่ต้องมีก่อน
- Node.js 22 ขึ้นไป (เครื่องนี้มี v24)
- Docker Desktop เปิดอยู่ (ไอคอนวาฬที่ taskbar ต้องขึ้นว่า running)
- Git Bash หรือ terminal ของ VS Code (คำสั่งด้านล่างเขียนแบบ Git Bash)
- ไฟล์ source/.env ตั้งค่าแล้ว (มีอยู่แล้วในเครื่องนี้ ห้ามแชร์ไฟล์นี้ให้คนอื่น เพราะมีรหัสลับ)


----------------------------------------------------------
A) รันทุกวัน (ปกติใช้แค่ส่วนนี้)
----------------------------------------------------------

1) เข้าโฟลเดอร์โค้ด
   cd /d/Personal/Projects/DevInventory/source

   อธิบาย: โค้ดและ package.json อยู่ในโฟลเดอร์ source/ คำสั่ง npm ทุกคำสั่งต้องรันจากที่นี่
   (ถ้าใช้ PowerShell พิมพ์: cd D:\Personal\Projects\DevInventory\source)

2) เปิดฐานข้อมูล PostgreSQL
   docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d db

   อธิบาย: เปิด container ชื่อ source-db-1 (PostgreSQL 17) แบบทำงานเบื้องหลัง (-d)
   ไฟล์ docker-compose.dev.yml เปิดพอร์ต 127.0.0.1:5433 ให้แอปบนเครื่องต่อได้
   ใช้พอร์ต 5433 ไม่ใช่ 5432 เพราะเครื่องนี้มี Postgres ตัวอื่นใช้ 5432 อยู่
   ถ้า container รันอยู่แล้ว คำสั่งนี้จะไม่ทำอะไร รันซ้ำได้ปลอดภัย

3) ตรวจความพร้อม
   npm run doctor

   อธิบาย: ตรวจว่า .env ครบ, ต่อฐานข้อมูลได้, migration ล่าสุด และมีบัญชี Admin
   ถ้าข้อไหนไม่ผ่าน มันจะบอกวิธีแก้ — รันข้อนี้ก่อนเสมอเมื่อมีอะไรผิดปกติ

4) อัปเดตโครงสร้างฐานข้อมูล
   npm run db:migrate

   อธิบาย: รันไฟล์ SQL ใน source/drizzle/ ที่ยังไม่เคยรัน (เรียงตามชื่อ 0000, 0001, 0002 ...)
   ถ้าไม่มีอะไรใหม่จะขึ้นว่า "migrations up to date" รันซ้ำได้ปลอดภัย

5) เปิดเว็บ (โหมดพัฒนา)
   npm run dev -- -p 3100

   อธิบาย: เปิด Next.js dev server ที่พอร์ต 3100 (แก้โค้ดแล้วหน้าเว็บอัปเดตเอง)
   ต้องใช้ -p 3100 เพราะพอร์ต 3000 บนเครื่องนี้มีโปรแกรมอื่น (Gotenberg) ใช้อยู่
   "--" ตรงกลางคือการส่ง -p 3100 ต่อให้ next ไม่ใช่ให้ npm
   รอจนขึ้น "Ready" แล้วเปิดเบราว์เซอร์ที่  http://localhost:3100
   ครั้งแรกที่เปิดแต่ละหน้าอาจช้า 2–5 วินาที เพราะ dev server compile หน้านั้นก่อน

6) เข้าสู่ระบบ
   อีเมล: admin@example.com  (รหัสผ่านคือรหัสที่ตั้งไว้ — ไม่เขียนไว้ในไฟล์นี้)
   สำคัญ: ก่อนพิมพ์รหัส ให้ดูว่าแป้นพิมพ์เป็นภาษาอังกฤษ (ENG มุมขวาล่าง)
   ถ้าพิมพ์ตอนเป็นแป้นไทย ตัวเลข 1-5 จะกลายเป็น ๅ / - ภ ถ แล้วรหัสจะผิด

7) ปิด
   - ปิดเว็บ: กด Ctrl+C ใน terminal ที่รัน npm run dev
   - ปิดฐานข้อมูล (ไม่จำเป็น ปล่อยรันไว้ได้):
     docker compose -f docker-compose.yml -f docker-compose.dev.yml stop db
     อธิบาย: หยุด container แต่ข้อมูลยังอยู่ครบ เปิดใหม่ด้วยคำสั่งข้อ 2


----------------------------------------------------------
B) ทำเมื่อจำเป็นเท่านั้น
----------------------------------------------------------

ติดตั้งแพ็กเกจ (ครั้งแรก หรือทุกครั้งที่ package.json เปลี่ยน)
   npm install

   อธิบาย: ดาวน์โหลด library ลง node_modules/ ไฟล์ .npmrc ตั้ง legacy-peer-deps ไว้แล้ว
   (better-auth ขัดกับ peer dependency ของ vite) ไม่ต้องใส่ flag เพิ่ม
   ถ้าขึ้นคำเตือน allow-scripts ของ esbuild ไม่ต้องสนใจ ไม่กระทบการทำงาน

สร้างบัญชี Admin คนแรก (เฉพาะฐานข้อมูลใหม่ที่ยังไม่มีผู้ใช้)
   npm run db:seed

   อธิบาย: สร้าง Workspace + Admin จาก INITIAL_ADMIN_EMAIL / INITIAL_ADMIN_PASSWORD ใน .env
   ถ้ามีผู้ใช้อยู่แล้วจะข้าม ไม่ทำอะไร · Admin ที่สร้างใหม่ต้องเปลี่ยนรหัสตอน login ครั้งแรก
   (ระบบไม่มีปุ่มสมัครเอง ผู้ใช้คนอื่นต้องได้ลิงก์เชิญจาก Admin › ผู้ใช้)

ล้างฐานข้อมูลทิ้งทั้งหมดแล้วเริ่มใหม่ (ข้อมูลทุกอย่างหาย!)
   docker compose -f docker-compose.yml -f docker-compose.dev.yml down -v
   docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d db
   npm run db:migrate
   npm run db:seed

   อธิบาย: down -v ลบ container และ volume ข้อมูล แล้วสร้างใหม่จากศูนย์
   ใช้เมื่อฐานข้อมูลพัง หรือขึ้น "password authentication failed" เพราะ volume เก่าจำรหัสเดิม
   หลังจากนี้ต้อง login ด้วยรหัสใน .env และตั้งรหัสใหม่


----------------------------------------------------------
C) ทดสอบ
----------------------------------------------------------

ตรวจ type ของ TypeScript
   npm run typecheck
   อธิบาย: หา error ของชนิดข้อมูลทั้งโปรเจกต์ ไม่มี output = ผ่าน

Unit test
   npm test
   อธิบาย: รัน Vitest (ตอนนี้ 80 เคส: สิทธิ์, การค้นหา, รหัสผ่าน, ป้าย/tag, ไฟล์แนบ, ประวัติเวอร์ชัน) ไม่ต้องใช้ฐานข้อมูล

Build แบบ production
   npm run build
   อธิบาย: ตรวจว่า build ผ่านก่อน deploy · ห้ามรันตอน npm run dev เปิดอยู่ (ใช้โฟลเดอร์ .next ร่วมกัน)
   ปิด dev server ก่อน แล้วค่อยรัน

ทดสอบ API แบบ end-to-end (ต้องเปิดเว็บไว้ที่ 3100 ก่อน)
   B=http://localhost:3100 PY=python \
   PSQL="docker exec -i source-db-1 psql -U inventory inventory" \
   ADMIN_EMAIL=<อีเมล admin> ADMIN_PW=<รหัส admin> MEMBER_EMAIL=<อีเมลที่ยังไม่เคยใช้> \
   bash scripts/e2e-items.sh

   อธิบาย: ยิง HTTP จริงตรวจสิทธิ์ การสืบทอด 409 ป้าย/tag/Markdown ไฟล์แนบ และประวัติเวอร์ชัน (113 เช็ก) จบด้วย passed=… failed=…
   - PY=python เพราะ python3 บนเครื่องนี้เป็นแค่ทางลัดไป Microsoft Store
   - PSQL ใช้ psql ใน container เพราะเครื่องนี้ไม่ได้ติดตั้ง psql
   - สคริปต์จะเชิญ MEMBER_EMAIL เป็นสมาชิกใหม่ และนับจำนวนแบบ workspace ว่าง
     จึงควรรันกับ workspace ทดสอบที่ว่าง (ถ้ารันกับ workspace จริงที่มีข้อมูล ตัวเลขบางข้อจะไม่ตรง)
   - ถ้า admin ยังต้องเปลี่ยนรหัส สคริปต์จะเปลี่ยนให้เป็น Admin-New-Pass-77 อัตโนมัติ


----------------------------------------------------------
D) ปัญหาที่เจอบ่อย
----------------------------------------------------------

- เปิด localhost:3000 แล้วขึ้น "Not Found" ข้อความสั้น ๆ
  → นั่นคือ Gotenberg ไม่ใช่แอปนี้ ให้ใช้ http://localhost:3100

- หน้าเว็บโหลดไม่ครบ / editor ไม่ขึ้น / console มี 404 ของไฟล์ _next/static/...
  → มี dev server สองตัวรันในโฟลเดอร์ source พร้อมกัน (ใช้ .next ร่วมกันแล้วพัง)
    ปิดทุกตัว (Ctrl+C) แล้ว:  rm -rf .next  จากนั้นรัน npm run dev -- -p 3100 ตัวเดียว

- รัน npm run dev แล้วขึ้น "Port 3100 is in use"
  → มี dev server เปิดค้างอยู่ (เช่นที่ Claude เปิดในแผง Browser) ปิดตัวเดิม หรือใช้พอร์ตอื่น
    npm run dev -- -p 3200

- login ไม่ได้ ทั้งที่มั่นใจว่ารหัสถูก
  → ดูแป้นพิมพ์ว่าเป็นภาษาอังกฤษ
  → ใส่ผิด 5 ครั้งใน 15 นาที บัญชีถูกล็อก 15 นาที (ระหว่างนั้นรหัสถูกก็เข้าไม่ได้) รอ 15 นาทีแล้วลองใหม่

- แก้ไฟล์ .env แล้วไม่มีผล
  → กด Ctrl+C แล้วรัน npm run dev ใหม่ (dev server อ่าน .env ตอนเริ่มเท่านั้น)

- error อื่น ๆ
  → รัน npm run doctor ก่อน ถ้ายังไม่หาย คัดลอกข้อความ error เต็ม ๆ จาก terminal ไปถาม
